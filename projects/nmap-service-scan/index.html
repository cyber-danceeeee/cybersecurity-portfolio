Safe Localhost Service Enumeration

A deliberately narrow scan against an author-owned loopback service, designed to practise service detection without touching any third-party system.

RoleAnalyst
ToolsNmap, Python
Scope127.0.0.1 only
ObjectiveEnvironmentMethodResultsImprovements

01 / Objective

Enumerate without exceeding scope.

Practise a tightly scoped service-enumeration workflow and distinguish open and closed TCP ports without sending scan traffic to any third-party system.

02 / Environment & tools

A controlled target.

  • Author-owned macOS host
  • Nmap 7.98 and Python 3.12
  • Loopback target 127.0.0.1
  • TCP ports 22 and 8000 only

03 / Method

Start, verify, scan, clean up.

  1. Confirm localhost scope and two-port allowlist.
  2. Start a Python HTTP server bound only to loopback.
  3. Check that the process is ready.
  4. Run service detection against ports 22 and 8000.
  5. Interpret results, stop the server, and sanitise evidence.
nmap -sV -Pn -p 22,8000 127.0.0.1

04 / Results & evidence

One expected service, one closed port.

Port 8000 was open because the controlled Python service was listening. Port 22 was closed: the host responded, but no SSH service accepted the connection. The banner guided identification, but did not establish a vulnerability by itself.

PORT     STATE  SERVICE VERSION
22/tcp   closed ssh
8000/tcp open   http    SimpleHTTPServer 0.6

Evidence: sanitised result and safe reproduction script.

05 / What I would improve

Compare exposure with an approved baseline.

For a larger authorised lab, I would use an explicit target allowlist, preserve machine-readable results privately, verify banners manually, and compare each service with the expected baseline. An unexpected port would be closed at its source and verified with a second scan.

Authorised localhost scan only.
